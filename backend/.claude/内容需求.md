## 1. 模块定位与目标

一个由**关键词与参数驱动、Qwen 模型生成、AI 自动评分**的 GEO 内容生产工具。

面向 GEO（生成式引擎优化）场景，产出**结构化、面向"被搜索 / 被引用"**的内容。

**内容一律由 AI 生成，不提供人工撰写。** 主线如下：

```
   ┌─ 选智能体(7选1) ─┐
   │  配置创作参数     │──(可存为「模板」复用) ── M1
   └────────┬────────┘
            ▼
   AI(Qwen)生成正文(md) + 多标题备选 ────────────── M2
            ▼
   GEO评分(AI审判官, 7维) ──可反复── AI优化并替换 ─── M3 / M4
            ▼
   保存为历史记录(仅记 AI 生成内容, md 形式) ───────── M5
            ▼
   导出(md 为准, word 可选)
            ▼
   [发布后] 关键词命中验证 ────────────────────── M6 / M7
```

要点（本轮修正）：
- **内容只有 AI 生成一种来源**，不做手动录入/编辑正文来源；用户对生成结果的调整通过"AI 优化并替换"（M4）完成。
- **正文一律为 markdown**；历史记录只记录 AI 生成的内容。
- **基础信息（创作参数）可保存为「模板」**复用，模板 ≠ 内容，仅是参数预设。
- **标题需多备选方案**（AI 生成时产出多个标题）。
- **评分可反复触发**：生成后、AI 优化替换后都可再评分对比。

形态参照 EDA365·AI 内容生产器（智能体矩阵 + 创作参数面板 + 生成正文 + GEO评分报告 + 多格式下载）。

### 本期已知取舍（务必让开发知晓，避免误判为缺陷）

| 取舍 | 说明 | 后续 |
|---|---|---|
| 事实来源不做校验 | Qwen 生成内容的事实真实性本期不做外部核验，接受风险、人工兜底 | 验证价值后搭知识库，入口为"辅助资料融合" |
| 7 智能体不共享事实层 | 各智能体独立生成，跨文事实一致性本期不处理 | 后续统一事实源 |
| 搜索引擎命中 ≠ 被 AI 引用 | 命中验证查的是搜索引擎收录/可见性，作收录探针用，不等于 GEO 被引用效果 | 后续再做 AI 引擎监控 |

## 2. 核心数据模型（开发优先看这里）

各功能块围绕以下实体与关联展开。**关联关系是本模块的骨架，接口都挂在这套关系上。**

```
Template(创作参数模板)          ← 仅存参数预设，可复用，不含内容
  └── 关联 Agent + 各创作参数

Content(内容, 仅 AI 生成)         ← 历史记录即 Content 列表
  ├── body 一律为 markdown
  ├── 1:N  ContentVersion(版本)   ← 每次生成/AI优化替换产生新版本
  ├── 1:1  Score(GEO评分报告)      ← 可多次评分, 关联到版本
  ├── 1:N  Image(配图)
  ├── N:M  Keyword(关键词)          ← 关键词可复用于多内容
  ├── 1:N  PublishUrl(发布地址)      ← 发布后回传，本期预留
  └── 关联 Agent(智能体)

CrawlResult(命中结果)
  └── 关联  (Keyword + PublishUrl + SearchEngine)   ← 命中验证的落点
```

说明：
- **Template（模板）**：只保存创作参数（智能体+受众+平台+行业+角度+关键词+字数+额外要求），供下次一键载入，**不保存正文**。
- **Content（内容）**：只由 AI 生成，`body` 必为 markdown；历史记录 = Content 列表。**无手动录入来源**。
- 已移除原 Suggestion 实体（优化改为"优化并替换"，直接产生新版本，不单独存建议）。

**贯穿主键**：`content_id`、`keyword_id`。命中验证链路为：
`content_id → keyword_id → publish_url → crawl_result`

> 【待澄清·P0】是否本期就预留 `PublishUrl` 与关联表。**强烈建议预留**，否则发布环节接入时数据结构返工。

# M1　创作配置域（含模板）

## 功能说明
提供智能体清单、创作参数选项，以及**创作参数模板的保存/载入**（基础信息保存 = 存模板，不存内容）。对应图中"智能体矩阵""创作参数""自定义关键词""目标字数""额外要求/资料上传"。

## 业务规则
- 所有下拉枚举由后端统一下发，前端不硬编码，便于运营调整。
- 智能体固定 **7 个**（名称见 1.2），独立运行、各自提示词。
- "创作角度"含"随机(每次不同)"选项；选中后每次生成产出不同角度。
- **模板只存参数预设，不存正文**；用户可保存当前参数为模板，下次一键载入。
- 【已确认】创作参数字段集（据界面）：目的受众、发布平台、行业领域、创作角度、自定义关键词、目标字数、额外要求、资料上传（可选、可多传）。

## 交互流程
1. 用户进入创作页 → 前端调 1.1 拉参数枚举、1.2 拉智能体、1.3 拉已存模板。
2. 用户选 1 个智能体 + 填参数（或 1.4 载入模板）→ 可 1.5 存为新模板 → 进入 M2 生成。

## 接口清单

### 1.1 GET /config/options — 获取创作参数选项
- 入参：无
- 出参（每项元素 `{ code, label }`）：
  - `audiences[]` 目的受众（如 中高级工程师/初级工程师/高校学生/硬件团队负责人）
  - `platforms[]` 发布平台（微信公众号/知乎CSDN/电子论坛/B站抖音/头条百家号）
  - `industries[]` 行业领域（如 通用/工业控制/医疗电子/通信5G/汽车电子/消费电子/嵌入式IoT）
  - `angles[]` 创作角度（如 痛点切入/随机(每次不同)/…）
  - `wordCountLevels[]` 目标字数档（如 ~800短/~1500标准/~1800中篇/~2500长文）
- 【待澄清】各枚举的完整取值清单需业务最终确认（上为据界面推断的候选）。

### 1.2 GET /agents — 获取智能体列表
- 入参：无
- 出参：`agents[]: { agentId, name, icon, description, enabled }`
- 【已确认】7 个智能体（据界面）：方案设计智能体、元器件提参建库智能体、PCB设计智能体、器件优选智能体、器件优购智能体、PCB预审报价智能体、PCB工艺审查智能体(DFM)。

### 1.3 GET /templates — 模板列表
- 出参：`items[]: { templateId, name, agentId, params, createdAt }`

### 1.4 GET /templates/{templateId} — 模板详情
- 出参：完整参数预设，供前端回填面板

### 1.5 POST /templates — 保存模板
- 入参：`name` `agentId` + 全部创作参数
- 出参：`templateId`

### 1.6 DELETE /templates/{templateId} — 删除模板
- 出参：操作结果

## 字段说明
| 字段 | 含义 | 备注 |
|---|---|---|
| code/label | 枚举编码与展示名 | code 存库，label 展示 |
| angle="random" | 随机角度 | 触发每次生成不同角度 |
| params | 模板承载的创作参数集 | 不含正文，仅参数 |

# M2　内容生成域（Qwen，唯一内容来源）

## 功能说明
按创作参数 + 提示词调用 **Qwen 生成正文**，这是内容的**唯一来源**（不提供人工撰写）。生成为异步任务。产出正文（md）+ 多个标题备选。

## 业务规则
- **内容只由 AI 生成**；无手动录入正文来源。
- 正文一律为 **markdown**。
- 生成时产出**多个标题备选**（供用户挑选/替换）。
- 提示词负责约束：文风、结构、角度、字数；不负责事实正确性（本期取舍）。
- "随机角度"下，`regenerate` 每次产出不同版本，均作为新版本入库（M5.4）。
- 生成成功即落库为一条 Content（历史记录），返回 contentId。
- `extraPrompt`（额外要求）与上传素材（资料上传，txt/md/json/csv）作为**生成时可选输入**注入正文；素材仅作写作参考，本期不做事实校验。
- 【待澄清】配图是否随正文同步生成，或走独立接口 M5.5。

## 交互流程
1. 用户选智能体 + 填参数（或载入模板）→ 点"生成" → 调 2.1，拿 taskId，前端 loading。
2. 轮询 2.2 直到 completed → 渲染正文（md）+ 标题备选。
3. 用户点"再次生成" → 调 2.3，产出新版本。
4. 生成结果自动进历史记录（M5）；后续可评分（M3）、AI优化替换（M4）、导出。

## 接口清单

### 2.1 POST /content/generate — 发起 AI 生成（异步）
- 入参：
  - `agentId` 智能体ID
  - `audience` `platform` `industry` `angle` `wordCount` 创作参数
  - `keywords` 自定义关键词（保持原样，GEO优化+文章生成用；文本，见 M6）
  - `extraPrompt` 额外要求（可空）
  - `materials[]` 上传素材（可选、可多传；txt/md/json/csv 解析后的文本）
- 出参：`taskId` `status`(pending)

### 2.2 GET /content/generate/{taskId} — 查询生成结果
- 入参：`taskId`
- 出参：
  - `status`(pending/running/completed/failed)
  - 完成时：`contentId` `body`(markdown) `titleOptions[]`(多个标题备选) `wordCount`
  - 失败时：`errorCode` `errorMsg`

### 2.3 POST /content/regenerate — 再次生成
- 入参：`contentId` + 可覆盖的创作参数
- 出参：同 2.1（新 taskId）；完成后产出新版本，挂同一 contentId 下

## 字段说明
| 字段 | 含义 | 备注 |
|---|---|---|
| body | 正文 | **一律 markdown**；保留结构供导出与机器可读 |
| titleOptions | 多个标题备选 | 用户可挑选/替换标题 |
| keywords | 自定义关键词 | 保持原有形态，兼作 M6 命中验证锚点 |
| materials | 生成参考素材 | 仅写作参考，不做事实校验 |
| status | 异步任务状态 | 前端据此控制 loading/重试 |

## 异常处理
- Qwen 超时/限流：返回 failed + 可重试标记，前端提示重试，不吞错。
- 参数缺失：400 + 明确字段名。

# M3　GEO 评分域（AI 审判官）

## 功能说明
对**编辑区当前内容**由 AI 模型以"审判官"角色打分，输出 7 维度 GEO 评分报告（对应图中"GEO评分报告 综合评分 85.2"）。

## 业务规则
- **评分不绑定内容来源、可随时反复触发**：用户手写的内容能打分、AI 生成的能打分、AI 优化替换后还能再打分。评分只针对"提交时的当前内容"。
- 纯 AI 打分，**分数即结论**，本期不接外部事实校验。
- 评分维度固定 7 项：结构化 / 信息密度 / 可引用性 / 语义覆盖 / 权威 / 可读性 / AI友好。
- 【已确认】为保证同一篇文章分数可复现：**固定模型 + 固定提示词 + 低温度**（否则达标线失效）。
- 每次评分记录留痕，可关联到当时的内容版本（M5.4），便于对比优化前后分数变化。
- 【待澄清】各维度权重值（图示"结构化(15%) 信息密度(15%)…"，需给全）。

## 交互流程
1. 用户在编辑区任意时刻点"评分" → 调 3.1（不要求内容必须由 AI 生成）。
2. 前端渲染综合分 + 各维分条 + 每维说明。
3. 用户可在手写/AI生成/AI优化后各评一次，对比分数。

## 接口清单

### 3.1 POST /content/{contentId}/score — 触发评分
- 入参：`contentId`（或直接传 `body` 支持未落库内容试评）
- 出参：
  - `overallScore` 综合分（如 85.2）
  - `grade` 等级（优秀/良好/…）
  - `dimensions[]: { name, score, weight, detail }` 7 维明细

### 3.2 GET /content/{contentId}/score — 读取最近评分
- 入参：`contentId`
- 出参：同 3.1 最近一次结果 + `scoredAt`

## 字段说明
| 字段 | 含义 | 备注 |
|---|---|---|
| overallScore | 加权综合分 | 各维 score × weight |
| dimensions[].detail | 该维评语 | AI 生成的说明文字 |
| weight | 维度权重 | 待业务给定 |

## 异常处理
- AI 打分失败：返回可重试，不阻塞内容保存。

# M4　AI 优化域（优化并替换）

## 功能说明
【已确认】用户**主动选择**让 AI 优化编辑区里的已有内容（无论手写还是 AI 生成），**AI 优化后直接产出优化版本替换原内容**（人可确认/撤销），不是只给一段建议文字。

## 业务规则
- **AI 优化是可选动作，由用户主动触发**，非必经步骤。
- 优化的输入 = 编辑区当前内容（+可选优化指令，如"更口语化""补充数据"）。
- 优化的输出 = 完整替换后的内容，回填编辑区；原内容留为历史版本（M5.4），支持撤销/回退。
- 优化后可再次评分（M3）对比效果，也可再次优化，可反复。
- 优化同样由 Qwen/大模型完成，事实正确性本期不校验（同 M2 取舍）。
- 用户对可填写字段（标题、正文、关键词等）的选择性优化：可整篇优化，也可指定字段/段落优化。
- （原 Q8「给建议 vs 改字段」已由需求方拍板为"优化并替换"，此待澄清作废。）

## 交互流程
1. 用户在编辑区点"AI优化"（可选填优化指令、可选定范围：整篇/某字段/某段）→ 调 4.1。
2. AI 产出优化后内容 → 前端展示"优化前/优化后"对比 → 用户确认替换或撤销。
3. 确认后回写内容、生成新版本；可继续评分或再次优化。

## 接口清单

### 4.1 POST /content/{contentId}/optimize — AI 优化内容（异步）
- 入参：
  - `contentId`
  - `scope` 优化范围（whole / field / section）
  - `target` 当 scope 非 whole 时，指定字段名或段落定位
  - `instruction` 可选优化指令（如"更口语化/补充案例/精简"）
- 出参：`taskId` `status`；完成后：`optimizedBody`(替换后内容) `diff`(可选，前后对比)

### 4.2 POST /content/{contentId}/optimize/apply — 确认替换
- 入参：`contentId` + `taskId`（或 optimizedBody）+ `action`(apply/discard)
- 出参：`action=apply` → 更新后的 `contentId` + 新 `versionId`；`discard` → 不改动

## 字段说明
| 字段 | 含义 | 备注 |
|---|---|---|
| scope | 优化范围 | 整篇/字段/段落 |
| instruction | 优化指令 | 用户可空，空则默认整体优化 |
| optimizedBody | 优化后内容 | 替换原内容，markdown |
| diff | 前后差异 | 供"优化前/后"对比展示，可选 |
| action | 确认动作 | apply 替换 / discard 撤销 |

## 异常处理
- 优化失败：保留原内容不变，提示重试，不吞错。

# M5　内容管理与导出域

## 功能说明
内容（历史记录）的存储、版本、列表筛选、配图、多格式下载。**历史记录只收录 AI 生成的内容，正文一律 md。**

## 业务规则
- **历史记录 = AI 生成内容列表**；不存手动录入内容（本期无此来源）。
- 存储正文**一律 markdown**；每次生成 / AI优化替换自动存为新版本，可回溯。
- 【已确认】导出以 **markdown 为准**；word 作为可选导出格式供人工发布用。
- 内容状态贯穿全生命周期。
- 【待澄清】内容状态机取值（建议：已生成 / 已评分 / 已优化 / 已发布 / 已下架）。

## 交互流程
1. 生成后自动保存草稿 → 用户可在列表查看、筛选、进详情。
2. 详情页可看正文、评分、关键词、版本、命中结果。
3. 用户点下载 → 选 md 或 word → 5.6 返回文件。

## 接口清单

### 5.1 POST /content — 保存/更新内容（AI 生成结果）
- 入参：内容体（选中标题/body(md)/keywords/agentId/参数/status）
- 出参：`contentId` `versionId`
- 说明：内容来源仅 AI 生成；本接口用于保存生成结果、选定标题、更新状态，不承接人工撰写正文。

### 5.2 GET /content/{contentId} — 内容详情
- 出参：正文、评分、关键词、状态、发布URL、最近命中结果聚合

### 5.3 GET /content — 内容列表（分页/筛选）
- 入参：`status` `agentId` `keyword` `dateRange` `page` `size`
- 出参：`items[]` + 分页信息

### 5.4 GET /content/{contentId}/versions — 版本列表
- 出参：`versions[]: { versionId, createdAt, summary }`

### 5.5 POST /content/{contentId}/images — 生成配图
- 入参：`contentId` + 配图参数
- 出参：`images[]: { imageId, url }`
- 【待澄清】配图随生成同步还是独立触发。GEO 上配图不加分，仅供人类读者/平台展示。

### 5.6 GET /content/{contentId}/export — 导出下载
- 入参：`contentId` `format`(md/word)
- 出参：文件流（md / docx）

## 字段说明
| 字段 | 含义 | 备注 |
|---|---|---|
| status | 内容状态 | 状态机待定 |
| versionId | 版本号 | 每次改动生成 |
| format | 导出格式 | md 主 / word 辅 |

# M6　关键词与命中验证域

## 功能说明
定义关键词及优先级；发布后由爬虫到搜索引擎检索，**以"搜索结果中是否出现该内容的发布 URL"判断命中**。

## 业务规则
- 关键词可复用于多个内容（N:M）。
- 关键词支持**优先级**。【待澄清·P0】优先级语义 = 排查询顺序 or 标内容权重。
- 命中判据【待澄清·P0】：完整 URL 精确匹配 / 域名+标题模糊匹配。
- 【待澄清·P0】查询的搜索引擎清单（百度/谷歌/必应/…）。
- 【依赖】命中验证依赖发布 URL（M7.1）。发布未接入前，可用测试 URL 跑通逻辑。
- 【已知取舍】命中 = 搜索引擎可见性，非 AI 引用效果。

## 交互流程
1. 编辑内容时录入关键词 + 优先级（6.1）。
2. 内容发布拿到 URL 后（M7.1）→ 发起爬虫检索（6.3）。
3. 轮询结果（6.4）→ 命中/未命中回写内容，展示在详情与趋势（6.5）。

## 接口清单

### 6.1 POST /keywords — 定义关键词
- 入参：`keyword` `priority` `contentId`(关联)
- 出参：`keywordId`

### 6.2 GET /keywords — 关键词列表
- 入参：筛选参数
- 出参：`items[]: { keywordId, keyword, priority, relatedContentIds[] }`

### 6.3 POST /crawl/check — 发起爬虫检索（异步）
- 入参：`keywordId[]`（或 `contentId`）+ 可选 `searchEngines[]`
- 出参：`taskId`

### 6.4 GET /crawl/check/{taskId} — 查询检索结果
- 出参：
  - `status`
  - `results[]: { keyword, searchEngine, hit(bool), matchedUrl, rank, checkedAt }`

### 6.5 GET /crawl/results — 历史命中记录
- 入参：`contentId` / `keywordId` 筛选
- 出参：命中趋势、最近状态

## 字段说明
| 字段 | 含义 | 备注 |
|---|---|---|
| priority | 关键词优先级 | 语义待定 |
| hit | 是否命中 | 依命中判据 |
| matchedUrl | 命中到的 URL | 与发布URL比对 |
| rank | 排名位置 | 若判据含前N |

## 异常处理
- 爬虫被封/超时：标记该次检索失败可重试，不影响历史数据。
- 反爬限流：需限速/重试策略（开发定）。

# M7　关联与历史域

## 功能说明
贯穿"内容 ↔ 关键词 ↔ 发布URL ↔ 命中结果"的关联视图，及生成历史记录。

## 业务规则
- 关联模型是命中验证链路的骨架：`content_id → keyword_id → publish_url → crawl_result`。
- 【待澄清·P0】是否本期预留 7.1（发布URL回传）。**建议预留**，否则发布接入返工。
- 发布环节本期不实现，但 7.1 接口与关联结构先建好。

## 交互流程
1. 发布环节（后续）拿到 URL 后回调 7.1 写入。
2. 详情页调 7.2 聚合展示：这篇内容用了哪些关键词、发到哪些 URL、各 URL 命中情况。
3. 首页/历史页调 7.3 展示生成历史。

## 接口清单

### 7.1 POST /content/{contentId}/publish-url — 回传发布地址【预留】
- 入参：`platform` `url` `publishedAt`
- 出参：`publishUrlId`

### 7.2 GET /content/{contentId}/relations — 关联聚合视图
- 出参：`keywords[]` `publishUrls[]` `crawlResults[]` 聚合

### 7.3 GET /history — 生成历史
- 入参：分页参数
- 出参：`items[]: { contentId, title, agentId, createdAt, overallScore }`

## 字段说明
| 字段 | 含义 |
|---|---|
| publishUrlId | 发布地址记录ID |
| relations | 内容全关联聚合 |

# 全局约定

## 通用响应结构
建议统一：`{ code, message, data }`；异步任务统一 `{ taskId, status }` + 轮询/回调。

## 状态与枚举（需业务补齐）
- 内容状态机：草稿 / 已生成 / 已评分 / 已发布 / 已下架（待定）
- 异步任务状态：pending / running / completed / failed

## 大模型调用约定
- 生成（Qwen）与评分（审判官）均为大模型调用，需：超时控制、失败重试、限流保护。
- 评分接口固定模型 + 提示词 + 低温度，保证可复现（见 M3）。

## 非功能性要求
- 生成/评分/爬虫均为耗时任务，一律异步 + 状态查询，前端不长时间阻塞。
- 爬虫需限速与反爬容错。
- markdown 正文需在存储与导出全链路保持结构不丢失。
