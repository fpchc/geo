# OpenAPI 作为前后端契约源，前端生成类型 + 手写薄客户端

后端 FastAPI 已提供 OpenAPI，前端手写类型已经出现与真实响应漂移的迹象（状态枚举、缺失接口）。我们决定以 OpenAPI 为唯一契约源：用 `openapi-typescript` 生成类型并入库，业务侧只写薄客户端复用 `requestClient` 与统一响应封装；契约漂移由 CI 检查。

## Consequences

- 后端接口变更必须先更新 OpenAPI，再重新生成前端类型。
- 上传、下载、导出等非标准请求保留手写封装。
- CI 需要在契约漂移时失败，否则生成类型会退化为一次性产物。
