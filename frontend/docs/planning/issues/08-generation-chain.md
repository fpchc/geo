# 08 · 收敛内容生成链路契约与稳定性

Type: grilling
Status: open
Blocked by: 01

## Question

生成链路已定为「提交 + 轮询」，需要把契约、状态机和异常处理收敛到可上线。

需要明确：

- 生成/重生成的请求与响应字段；`GenerateAccepted` 的 `content_id + task_id + status + regen_count` 是否够用。
- `X-Idempotency-Key` 的生成、重试与重复提交语义；后端目前注掉了 `require_idempotency_key`，契约如何约定。
- 任务轮询的间隔、超时、退避、最大次数；页面离开/刷新后的任务恢复。
- 409 锁定、生成失败、评审失败、任务过期的用户提示与可重试边界。
- 评审触发与防重；评分查询的时机。
- 导出接口契约：格式、权限、文件名、下载方式（后端实现为外部依赖）。
- 是否保留 SSE 作为后续增强，以及前端是否预留适配层。

输出：前后端契约、状态机与 UI 状态映射、异常矩阵、验收场景。
